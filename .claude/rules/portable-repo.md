# Portable-Repo & Generated-File Hygiene

Companion to the gitleaks secret-scan gate in CLAUDE.md §3: that gate catches
credentials, this rule catches paths, usernames, and machine-identifying
config that aren't secrets but still shouldn't be in a public repo. Written
after auditing `~/.claude` post-push and finding 12 tracked files with
hardcoded `/Users/paulmckay` paths, two of which were generated runtime
artifacts that should never have been tracked at all.

- Before committing a new machine-specific value (a real filesystem path, a
  personal endpoint, a one-off local setting), check whether it belongs in
  `settings.local.json` instead of `settings.json`. `settings.local.json` is
  gitignored; `settings.json` is public.
- Never hardcode an absolute path (`/Users/paulmckay/...`) in a tracked file.
  Use `$HOME`, `~`, or a relative path if the consuming tool supports
  expansion; if it doesn't, move the real value to `settings.local.json` (or
  another gitignored override file) and commit a `*.example.json` template
  in its place.
- Before `git add`-ing a new file, check whether it's generated output — a
  file whose own header says "Generated by X — do not edit manually," a
  cache, a compiled artifact, a runtime log. Generated files belong in
  `.gitignore`, not in a commit: regenerate, don't version.
- `~/.claude` is a public repo with branch protection active on `main` — any
  fix here lands via the normal worktree → PR flow (CLAUDE.md §3's
  "Worktree merge pattern"), not a direct push.
- Don't rewrite existing git history to scrub already-pushed paths unless a
  genuine secret (not just a username/path) turns up — a disruptive
  history rewrite isn't worth it for cosmetic exposure. If a real secret is
  found, that's the one case a rewrite plus credential rotation earns its
  cost.
- Worked example and rationale: `/teach` workspace at
  `~/Desktop/learning/github`, Lesson 5
  (`lessons/0005-portable-repos-paths-and-generated-files.html`).
