# Divergent Ideation

Ordinary idea generation converges on the first workable answer because it optimizes for safety. This skill does the opposite: force distance from the obvious answer using named techniques, then rank by novelty so the unusual options survive long enough to be considered.

Output is range, not a single pick. Converge only when asked.

## When to use vs. brainstorming

- **This skill**: open-ended option generation — naming, positioning, angles, "what could I build/write/call this." No commitment to build yet.
- **brainstorming**: the user has already committed to building something and needs requirements + a design. This skill can feed into it — run this first, then hand the chosen direction to `brainstorming` — but does not replace it.

## Process

1. **Pin the constraints**: domain, goal, hard limits, and anti-goals — what the answer must NOT be. Anti-goals matter as much as the goal; they're what keep ideas from collapsing back to the obvious.
2. **Inject entropy** — apply at least two named techniques (naming lets the user say "more like that"):

| Technique | How to apply it |
|---|---|
| Inversion | Solve the opposite problem, then flip the answer back |
| Domain-collision | Borrow a mechanism from an unrelated field, force-fit it here |
| Constraint-flip | Remove the constraint everyone assumes, or add an absurd one |
| Scale-shift | Do it for 1 person, then for 10 million — what changes? |
| Audience-swap | Build it for the wrong audience: a child, an expert, an enemy |
| Time-warp | How would this be done in 1900? In 2100? |
| Subtraction | Remove the most "essential" part — what's left? |
| Analogy-mining | "This is like ___." Chase the analogy to its consequences |

3. **Generate 5-10 ideas**, each in a fixed shape: Name, Pitch (one line), Core insight (why it could work), Source technique, Risk (main reason it might fail), Cheap signal (smallest test that would validate or kill it). Force at least one idea that makes you wince or laugh — if nothing's uncomfortable, entropy wasn't high enough.
4. **Rank by novelty, not feasibility.** Ranking by buildability quietly re-sorts the safe idea back to the top and defeats the exercise.
5. **Converge only when asked.** Offer to narrow to the most promising candidates, but don't collapse to the comfortable option by default.

## Output

A ranked idea list (most novel first) in the Name/Pitch/Insight/Source/Risk/Signal shape, plus which techniques were used so the user can ask for more from a specific one.
