# docs-site

A local, personal-reference [Blume](https://github.com/haydenbleasel/blume) docs site for the "thin-harness, fat-skills" `~/.claude` setup. Not published — no git remote is configured on the parent repo, and none is added here.

## Running it

```bash
cd docs-site
npm install     # first time only
npm run dev     # runs `npm run sync` first, then `blume dev`
```

The site's base path is configured for GitHub Pages deployment, so local
`npm run dev` serves it at `http://localhost:4321/brain` — not the bare
root `/`.

## How content is organized

Three kinds of content coexist under `content/`, and each kind has a different update path:

1. **Auto-pulled** — `content/skills/**/*.md`. Generated by `scripts/pull-skills.mjs` from every `skills/*/SKILL.md` (plus nested reference files, e.g. `senior-engineering-partner/references/*.md`). **Never hand-edit these** — they're overwritten on the next sync. Edit the source `SKILL.md` instead.
2. **Hand-authored / Claude-drafted** — everything else that isn't a stub, written directly as normal markdown/MDX.
3. **Linked-not-duplicated** — stub pages (`content/overview/*.md`, `content/openwolf.md`) that summarize a source of truth living elsewhere in the repo (`CLAUDE.md`, `.claude/rules/openwolf.md`) rather than mirroring its full prose. Each stub names its source at the bottom of the page.

## The sync script

`npm run sync` (= `node scripts/pull-skills.mjs`) walks `../skills/`:

- Skips any skill directory with no `SKILL.md` (e.g. `ba-agent`, which is an agent definition, not a skill) — silently, no warning.
- Warns (but still writes a page) if a `SKILL.md` is missing its `name` or `description` frontmatter field.
- Follows symlinked skill directories (skills provided via the `superpowers` submodule are installed as symlinks, e.g. `skills/brainstorming -> ~/.claude/superpowers/skills/brainstorming`) by resolving with `statSync` rather than trusting `Dirent.isDirectory()`, which does not follow links.
- Writes each skill to `content/skills/<skill-name>.md`, and walks the skill directory for any other `.md` files, writing them as nested sub-pages at `content/skills/<skill-name>/<path>.md` — except for a fixed denylist of OSS-repo scaffolding filenames (`CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `MAINTAINERS.md`, `CHANGELOG.md`, `LICENSE*`).
- Is idempotent and only ever writes under `content/skills/` — it never touches hand-authored content elsewhere in the tree.
- Runs automatically as a `predev`/`prebuild` step, so the skills section can't go stale relative to whatever's currently in `skills/`. Run it manually any time with `npm run sync`.

Tests: `npm test` (or `node --test scripts/*.test.mjs`).

## Extending it

- **New skill?** Nothing to do — the next `npm run sync` (or `npm run dev`/`npm run build`) picks it up automatically.
- **New overview/stub page?** Add a markdown file under `content/overview/`; it appears in the nav automatically (no `meta.ts` — pages render in default alphabetical order for this pass).
- **Filling in a stub with full prose?** Edit the file directly under `content/overview/` or `content/openwolf.md` — these are hand-authored and the sync script never touches them.
