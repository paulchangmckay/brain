# Dispatch Sequencing Template

Template for `.claude/ORCHESTRATION.md`, written by Phase 5. This
documents a call sequence — there is no live team to configure, since
this repo doesn't use Agent Teams.

## Template

```markdown
# <Project> Agent Team — Orchestration

Generated by agent-team-architect on <date>. Re-run agent-team-architect
against this project to extend, or to audit for drift.

## Agents

| Agent | Role | Model | Skill(s) used |
|---|---|---|---|
| <name> | <one-line role> | <haiku/sonnet/opus> | <skill-name, or "global: <name>"> |

## Dispatch sequence

### Phase: <name>
**Pattern:** <Pipeline / Fan-out-fan-in / Expert pool / Producer-reviewer / Supervisor / Hierarchical delegation>
**Delegates to:** <"subagent-driven-development" if producer-reviewer, else "none — self-contained">

1. Dispatch `<agent-name>` with: <what it receives>
2. <next step, and so on>

Dependencies: <what must complete before this phase starts>

### Phase: <name>
...
```

## Notes for the generating agent

- One "Agents" table row per generated `.claude/agents/*.md` file — keep
  the model column in sync with the actual frontmatter, since Phase 0's
  drift detection diffs against this file.
- One "Dispatch sequence" section per Phase-2 pattern decision, even if a
  project only has one phase.
- When updating (not creating) this file per the Phase 0 extend/maintain
  matrix, edit only the affected Agents rows and Dispatch sequence
  sections — don't regenerate the whole document from scratch, so
  unrelated history in the file (if it's been hand-annotated) survives.
